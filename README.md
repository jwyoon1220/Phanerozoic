# Phanerozoic 엔진 문서

Phanerozoic은 사람이 없는 신생대 초(에오세) 지구를 걸으며 등산하고 채집하는 게임입니다. 이 문서는 그 게임을 위해 만든 C++20 / Vulkan 1.3 엔진을 설명합니다.

- **월드**: 실제 크기의 지구 전체를 하나의 구체로 다룹니다. 큰 지형은 실제 고도 데이터(1°)를 따르고, 그보다 작은 지형·재질·식생은 위·경도별 기후 규칙에 따라 절차적으로 생성됩니다. 지역 사이를 걸어서 이동하며 로딩 화면은 없습니다.
- **하늘**: 실제 별 목록과 천체 역학으로 게임 속 날짜·시각·위치의 하늘을 계산합니다.
- **최적화**: 최우선 과제입니다. 1440p에서 장면에 따라 GPU 3–9 ms를 씁니다(§11).

## 1. 빌드와 실행

### 요구 사항

| 항목 | 내용 |
|---|---|
| 컴파일러 | C++20 (GCC 13+ / Clang 17+) |
| CMake | 3.28 이상 |
| GPU | Vulkan 1.3 (dynamic rendering, synchronization2, buffer device address, descriptor indexing, scalar block layout) |
| 시스템 패키지 | Vulkan 헤더, GLM, `glslc`(셰이더 컴파일), 선택: GLFW 3.4, HDF5(전 지구 DEM 베이크), libtiff(30 m DEM), Python 3(Poly Haven 에셋) |
| 자동으로 받는 의존성 | volk 1.4.304, VMA 3.3.0, cgltf 1.14, meshoptimizer 0.22, stb, Jolt Physics 5.2.0, (없으면) GLFW 3.4 |

### 빌드

```sh
cmake -S . -B build
cmake --build build
./build/Phanerozoic
```

첫 빌드에서 원본 데이터를 내려받아 베이크합니다(§10). 원본은 `data/raw`, 베이크 결과는 `build/data/`에 저장됩니다.

| CMake 옵션 | 기본값 | 설명 |
|---|---|---|
| `PHX_BUILD_TESTS` | ON | `phx_job_tests`, `phx_astro_tests` |
| `PHX_ENABLE_TSAN` | OFF | ThreadSanitizer 빌드 |
| `PHX_DEM30_CELLS` | `33x109;33x110;34x109;34x110` | 베이크할 Copernicus 30 m 셀(남서쪽 모서리 위도x경도) |

테스트는 `ctest --test-dir build`로 실행합니다.

## 3. 스레드 모델과 잡 시스템

```
메인 스레드 = 수퍼바이저  GLFW 이벤트, 입력, 60 Hz 고정 시뮬레이션 틱, 물리, 스냅샷 발행
렌더 스레드              Vulkan 큐 제출과 프레젠트를 독점, 프레임 갱신
워커 N개                 종류 구분 없이 아무 잡이나 처리 (지형 타일, 식생 셀, 충돌 구역, 커맨드 기록)
```

- **수퍼바이저**: 남는 시간이 있을 때만 잡을 돕습니다(`supervisorHelp`). 대상은 `kSupervisorSafe` 플래그가 있고 예상 비용(`costHintUs`)이 남은 시간 안에 들어가는 잡뿐입니다. 입력 지연은 2 ms 이하로 유지합니다.
- **렌더 스레드**: 큐와 스왑체인을 혼자 소유합니다. 커맨드 버퍼 기록은 Critical 잡으로 던지고, 워커마다 전용 커맨드 풀을 씁니다.
- **잡 시스템** (`engine/jobs`):
  - 스레드마다 Chase-Lev 워크 스틸링 데크가 있고, 우선순위는 3단계(Critical → Normal → Background)입니다.
  - 외부 스레드가 제출한 잡은 주입 큐로 들어갑니다.
  - 잡 크기는 128 B 고정이고, 람다 페이로드는 최대 96 B입니다. 프리리스트에서 할당하므로 매 프레임 힙 할당이 없습니다.
  - `Counter`는 의존성과 대기에 씁니다. `pending_`과 `visible_`을 나눠서 마지막으로 감소시킨 스레드가 카운터에 더는 접근하지 않게 했습니다(TSan으로 검증).
  - `parallelFor`는 범위를 재귀적으로 반으로 나눠 오른쪽 절반을 다른 스레드가 훔쳐 가게 합니다.
  - 워커는 짧게 스핀한 뒤 `std::atomic::wait`로 잠듭니다.
- **스냅샷**: 수퍼바이저가 `FrameSnapshot`(카메라, 하늘, 노출, HUD, 성능 오버레이 플래그 등)을 `TripleBuffer`에 발행하고, 렌더러는 최신 스냅샷만 읽습니다. 락이 없습니다.

## 4. 프레임 흐름

**수퍼바이저 틱 (60 Hz)**: 입력 → 플레이어 물리 또는 비행 카메라 → 환경(시계, 관측자, 하늘, 노출 적응) → 스냅샷 발행.

**렌더 스레드 (프레임마다)**:

1. 타임라인 세마포어를 기다립니다(동시에 2프레임까지). 이어서 스왑 이미지를 얻고 GPU 타이머를 읽습니다.
2. CPU 갱신(약 0.6–0.9 ms):
   - 지형 높이맵 그림자 중심과 CSM 행렬을 계산합니다.
   - 프레임 유니폼을 채웁니다.
   - 지형 LOD를 선택하고 타일 스트리밍 잡을 던집니다.
   - 식생 셀 스트리밍과 업로드를 준비합니다.
   - 성능 오버레이와 HUD를 구성합니다.
3. 커맨드 기록 잡(워커). 패스 순서:

| 순서 | 패스 | 내용 |
|---|---|---|
| 1 | skyLUT | 대기 LUT: 투과율, 다중 산란, 해·달 하늘색 |
| 2 | upload | 지형 타일·식생 셀 업로드, 지형 그림자 높이맵, 그림자 가시도 컴퓨트 |
| 3 | csm | 그림자 캐스터 컬링 → 캐스케이드 3장에 나무·바위 깊이 렌더 |
| 4 | terrain | HDR과 깊이(reverse-Z) 클리어, 지형 그리기 |
| 5 | hiz+cull | 이번 프레임 지형 깊이로 Hi-Z 피라미드 생성 → 식생 컬링(절두체, Hi-Z, LOD) |
| 6 | forest | 식생 메시와 임포스터를 간접 그리기 |
| 7 | sky+stars | 하늘, 해, 달, 행성, 별 |
| 8 | tonemap | 노출, ACES, 암소시(야간 시각), 디더 → 스왑체인, 그 위에 오버레이와 HUD |

4. 제출 → 프레젠트. F12나 스크립트 스크린샷이면 스왑 이미지를 복사해 PNG로 저장합니다.

## 5. 좌표계와 정밀도

| 공간 | 용도 |
|---|---|
| ECEF (double) | CPU의 모든 월드 위치. 구형 지구, 반지름 6 371 km, z = 북극, x = 경도 0° |
| 카메라 기준 ECEF (float) | GPU 정점. 타일과 셀의 중심 − 카메라를 CPU에서 double로 빼서 넘기므로 행성 규모에서도 떨림이 없습니다 |
| ENU | 카메라의 지역 동·북·위 좌표. 하늘, 조명, 대기에 사용 |
| `cameraMod` | 카메라 ECEF를 65 536 m로 나눈 나머지(double로 계산). 텍스처·노이즈 좌표를 월드에 고정할 때 씁니다. `cameraEcef + rel` 같은 float 계산은 0.5 m 단위 반올림 이음매를 만들기 때문입니다 |
| 물리 지역 좌표 (Jolt) | 플레이어 근처 지면을 원점으로 x = 동, y = 위, z = 남. 24 m 이동마다 원점을 다시 잡습니다 |

깊이는 reverse-Z, float32, 원평면이 무한대인 투영입니다. near 평면은 지면 위 높이 × 0.05(0.05–1000 m)로 정합니다.

## 6. 월드 생성

### 6.1 높이 (`engine/world/HeightField`)

`height(dir, resolutionM)`은 순수 함수이고 여러 스레드에서 안전하게 호출할 수 있습니다. 지형 타일, 식생 배치, 물리, 그림자가 모두 같은 함수를 씁니다. `surface(dir, res)`는 높이와 함께 지형 특징(절벽, 너덜, 모래, 산악도)과 기후를 돌려줍니다.

1. **기반 고도**: PALEOMAP 0 Ma 1° DEM(현대 지리)을 bicubic으로 보간합니다. 에오세 보정으로 해수면을 +70 m 올리고, 티베트를 낮추고, 극지 빙상을 없앱니다.
2. **산악도** (0.25° 격자): 1° 고도와 그 기울기로 산맥 벨트를 찾습니다. 판정은 기울기 위주이고 고도는 보조입니다. 그래서 고원은 산지로 판정되지 않습니다.
3. **절차 지형** (`globalSurface`):
   - **능선**: 도메인 워핑한 ridged multifractal이고, 기본 파장은 24 km입니다. 진폭은 50 m + 1500 m × 산악도^1.2이며, 사막 평지에서는 절반으로 줄입니다.
   - **단층애**: 고도와 무관한 4 km 스케일 필드 C의 등치선을 따라 계단을 만듭니다(쿠에스타처럼 완만한 뒷면과 가파른 앞면). 절벽 면의 폭은 필드의 실제 기울기로 물리적 폭(12 m 이상, 정점 간격의 1.6배 이상)에 맞춥니다. 발치에는 연속적인 너덜 비탈 둔덕이 붙습니다. 높이는 35–165 m입니다.
   - **사구**: 사막의 평지 모래 지대에 바람 방향과 직각인 횡사구를 만듭니다. 파장 600 m, 높이 최대 34 m, 바람그늘 쪽 면은 약 30°입니다.
   - **미세 기복**: 48 m 이하 노이즈를 정점 간격의 4배보다 짧은 파장은 잘라 앨리어싱을 막습니다. 절벽 면에는 바위 덩어리 노이즈를 더합니다.
4. **30 m DEM** (선택, `PHX_DEM30=1`): Copernicus GLO-30 셀을 mmap으로 읽어 밉맵 bicubic으로 보간하고, 커버리지 경계에서 전 지구 층과 섞습니다.

> 같은 위치는 LOD 레벨이 달라도 같은 높이를 내야 합니다(CDLOD 모핑과 스커트). 해상도에 따라 형태가 바뀌는 항은 진폭이 작은 미세 항으로만 제한합니다. 단층애 폭이나 사구 페이드를 해상도에 따라 바꾸면 인접 LOD 사이에 틈이 생기고, 스커트가 빗살 모양 벽으로 드러납니다.

### 6.2 기후와 바이옴 (`engine/world/Climate`)

현대 기후를 규칙으로 근사합니다. 시작할 때 0.5° 격자(720×360)를 약 0.1초 만에 계산합니다.

- **기온**: 위도대별 해수면 평균 기온에서 시작해, 고위도 내륙일수록 낮춥니다. 질의할 때 실제 높이로 기온 감률(6.5 K/km)을 적용합니다.
- **계절 진폭**: 위도와 대륙도에 비례합니다. 가장 따뜻한 달 기온 = 연평균 + 진폭/2입니다.
- **강수**:
  - 위도대 기본값: 적도수렴대, 아열대 건조대, 편서풍 폭풍대.
  - 바람이 불어오는 쪽 수증기원까지의 거리로 줄입니다. 바람은 30° 아래는 무역풍(동쪽에서), 30–65°는 편서풍(서쪽에서), 그 위는 극동풍입니다. 바다는 350 km 이상 이어져야 수증기원으로 칩니다. 바다 판정은 현대 해안선 기준입니다.
  - 여기에 동안 몬순(아열대), 적도 쪽 몬순(남아시아·사헬), 산 너머 비그늘, 지형성 강수를 더합니다.
  - 규칙으로 맞지 않는 건조 핵심부(아라비아, 타르, 칼라하리, 호주 내륙, 소노라, 이란 고원)는 짧은 보정 목록으로 처리합니다.
- **바이옴 가중치** `biomeWeights(T, P, 진폭)`: 증발산량 PET를 구해 건조지수 AI = P/PET를 계산하고, 이것으로 연속적인 가중치를 정합니다. 경계가 부드럽게 섞입니다.

| 가중치 | 기준 |
|---|---|
| snow | 가장 따뜻한 달 < 약 1 °C |
| tundra | 가장 따뜻한 달 < 약 10 °C (수목한계) |
| forest | AI 0.32–0.62에서 닫힌 숲으로 |
| grass | 식생은 있으나 숲이 아닌 곳 |
| desert | AI < 0.1–0.4 |
| conifer | 연평균 11 → 3 °C |
| tropical | 연평균 16 → 22 °C |

시작 로그에 대표 지점의 판정이 찍힙니다. 예: 사하라 → hot desert, 시베리아 → taiga, 아마존 → tropical forest.

### 6.3 자연물 배치 (`engine/world/NaturePlacement`)

큐브 구 쿼드트리 셀 단위로 결정적으로 배치합니다. 시드는 셀 키입니다. 렌더러와 물리가 같은 함수를 쓰므로 둘이 보는 나무와 바위가 정확히 같습니다.

| 레이어 | 셀 크기 | 상주 반경 | 내용 |
|---|---|---|---|
| 14 | 약 610 m | 4.2 km | 나무 (후보 간격 약 6 m) |
| 16 | 약 150 m | 450 m | 볼더, 관목 |
| 18 | 약 76 m | 130 m | 양치류, 풀 덤불, 이끼 돌 |

- **나무**: 밀도는 숲 가중치(사바나는 성기게)에 경사, 숲 사이 빈터 노이즈, 절벽·모래·너덜 제외를 반영합니다. 수종은 추울수록 침엽수, 열대는 상록 활엽, 사바나는 건조지 소교목입니다.
- **볼더**: 너덜 비탈(절벽 발치), 급경사, 암석 사막과 툰드라에 놓습니다. 모래 위에는 놓지 않습니다.
- **풀·관목 색**: 건조지수로 정해 습하면 초록, 건조하면 짚색입니다.
- **바위**: 경사를 따라 기울이고 기울어진 만큼 더 묻습니다. 색은 사막 가중치로 칠합니다.
- **인스턴스 패킹**(16 B): 셀 기준 위치 float3와 32비트 = 종 4 | 회전 9 | 크기 9 | 색조 4 | 기울기 6.

종 목록(`kSpeciesCount = 9`)은 모두 Poly Haven CC0이고, 에오세 식물의 대역입니다.

| # | 에셋 | 역할 |

## 7. 렌더링

### 7.1 GPU 기반 구조

- **Vulkan 1.3**: dynamic rendering, synchronization2, 타임라인 세마포어를 쓰고 동시에 2프레임까지 진행합니다.
- **로더와 메모리**: volk, VMA. VMA는 `VK_EXT_memory_budget`이 있으면 활성화합니다.
- **바인드리스 디스크립터 세트 하나** (`Bindless`):
  - binding 0: 샘플 텍스처 1024개
  - binding 1: rgba16f 스토리지 이미지 64개
  - binding 2: r32f 스토리지 이미지 32개
  - 샘플러는 linear-clamp와 이방성 16× repeat(재질용)입니다.
- **버퍼는 전부 buffer device address로 전달합니다.** 푸시 상수 48 B: `frame`(FrameUniforms 주소), `stars`, `starCount`, `lightIndex`, `aux`, `aux2`, `aux3`. 패스마다 의미가 다릅니다.
- **FrameUniforms** (`SkyRenderer.hpp` ↔ `shaders/common.glsl`의 `FrameRef`; 두 정의를 반드시 같이 고칠 것):
  - 행렬: `viewProj`, `viewProjEcef`, `ecefToEnu`, `invViewProj`, `icrsToEnu`
  - 천체: 해·달 방향과 달 매개변수
  - 카메라, 해상도, 톤매핑
  - 지형 그림자 2장, CSM 3장
  - 바람, 계절
  - 컬링 매개변수, `cameraMod`
  - 지면 반사 알베도
- **바인드리스 텍스처 슬롯** (`SkyRenderer.hpp`):

| 슬롯 | 내용 |
|---|---|
| 0–3 | 투과율, 다중 산란, 하늘 LUT(해·달) |
| 4 | HDR |
| 5–8 | 지형 그림자 높이맵 근/원, 가시도 근/원 |
| 9 | 깊이 |
| 10–15 | 임포스터 알베도·노멀 (3종) |
| 20–22 | CSM 캐스케이드 |
| 32+ | 식생 재질: 32 + (종×8 + 재질)×3 + {알베도, 노멀, ARM} |
| 512+ | 지면 재질: 512 + 재질×3 + {알베도, 노멀, ARM} |

- **셰이더**: `shaders/*.vert|frag|comp`는 빌드할 때 `glslc`로 `build/shaders/*.spv`로 컴파일됩니다. 공용 include는 `common.glsl`(FrameRef, 푸시 상수), `atmosphere.glsl`, `lighting.glsl`(Surface, 조도, 대기 원근), `terrain_shadow.glsl`, `csm.glsl`, `normalmap.glsl`, `veg_common.glsl`입니다.

### 7.2 지형 (`TerrainRenderer`)

- **큐브 구 쿼드트리 + CDLOD**:
  - 타일은 65×65 정점에 테두리 스커트가 붙고, 최대 레벨 18(타일 약 76 m, 정점 간격 1.2 m)입니다.
  - 경계에서는 홀수 정점을 부모 격자로 모핑해 팝핑을 없앱니다.
  - 거리 왜곡 `d·(1 + (1 − e^(−d/20 km)))`로 원거리 LOD를 줄입니다.
- **컬링**: 지평선 컬링(차폐 원뿔)과 절두체 컬링을 하고, 앞에서 뒤 순으로 정렬해 간접 그리기 한 번으로 그립니다.
- **스트리밍**:
  - 타일 생성은 워커 잡이 double로 높이와 법선을 계산합니다.
  - 정점 풀은 4096 슬롯(약 420 MiB)이고, 배치 LRU로 축출합니다.
  - 동시에 진행하는 생성 잡은 워커 − 2개로 제한하고, 프레임당 업로드는 최대 48타일입니다.
- **정점 24 B**:
  - 위치 float3
  - 8진(octahedral) 법선 12+12비트와 높이 등급 8비트
  - `hintsA` = 모래 | 절벽 | 너덜 | 사막
  - `hintsB` = 숲 | 침엽수 | 눈 | 건조도
  - 바이옴과 지형 특징을 CPU의 높이·기후 모델에서 정점마다 계산해 넘기므로, 셰이더는 높이 함수와 정확히 일치하는 값을 씁니다.
- **셰이딩** (`terrain.frag`):
  - **가중치**: 경사와 절벽 → 바위, 눈, 모래, 숲 바닥(활엽 낙엽 / 침엽 낙엽, 흙 얼룩), 자갈 사막·너덜, 풀(건조도로 색 보정).
  - **근거리(약 1.4 km 이내)**: Poly Haven PBR 재질 9종을 삼평면 투영으로 블렌딩합니다. 노멀은 whiteout 블렌딩으로 합칩니다. 비중이 작은 층은 노멀맵을 생략합니다.
  - **밉 선택**: 분기 안에서 샘플링하므로 `textureGrad`로 명시적 기울기를 넘깁니다. 암시적 미분은 분기 안에서 정의되지 않아 밉이 깨지고 모아레가 생기기 때문입니다.
  - **원거리**: 재질 평균색과 숲 캐노피 색을 섞고, 대기 원근을 적용합니다.
  - **바다**: 프레넬 하늘 반사와 해 글린트를 그립니다.

### 7.3 그림자

| 범위 | 방식 |
|---|---|
| 0–700 m | **CSM** (`CascadedShadows`) 3장(30 / 150 / 700 m), 각 2048² D32. 경계 구 맞춤, 텍셀 스냅(월드에 고정된 광원 좌표, double), 4×4 PCF(textureGather 4회), 법선 오프셋과 기울기 비례 깊이 바이어스 |
| 근 6 km / 원 64 km | **지형 높이맵 그림자** (`TerrainShadows`) 2048² 두 장. 생성은 워커 잡이 하고, 해가 0.1° 이상 움직이거나 맵 중심이 바뀔 때만 가시도 컴퓨트(`shadowvis.comp`)를 다시 돌려 산 그림자를 계산합니다 |
| 700 m 밖 숲 | 캐노피 얼룩빛 근사 |

CSM 캐스터:
- 나무: 근거리 캐스케이드에서는 LOD2 메시, 먼 캐스케이드에서는 해를 향한 임포스터 쿼드입니다.
- 볼더와 건조지 소교목: 근거리 두 캐스케이드에만 그립니다.
- 잎 텍스처에는 알파가 없습니다(JPG). 그래서 밉 0의 검은 바탕을 잘라내 잎 모양만 그림자가 되게 합니다.

### 7.4 식생 (`VegetationRenderer`)

- **셀 스트리밍**: 384 슬롯 × 셀당 최대 8192 인스턴스입니다. 배치 잡은 워커가 돌리고, 프레임당 업로드는 최대 8셀입니다.
- **GPU 컬링** (`vegcull.comp`):
  - **카메라 모드**: 절두체 → Hi-Z 차폐(이번 프레임 지형 깊이) → 종별 LOD 거리(인스턴스마다 지터) 순으로 걸러 간접 그리기 버킷에 추가합니다.
  - **그림자 모드**: 카메라 절두체와 무관하게 캐스케이드별로 캐스터를 고릅니다.
  - **버킷**: 카메라 30개(종×LOD 3 + 임포스터 3)와 그림자 15개(캐스터 5 × 캐스케이드 3).
- **LOD**: 종마다 메시 LOD 3단계를 둡니다. 나무 3종은 약 4.1 km까지 8각면(octahedral) 임포스터를 씁니다. 임포스터는 시작할 때 원본 해상도 메시로 8×8 방향 × 256 px로 굽습니다.
- **셰이딩**:
  - 바람 흔들림, 단풍(계절)
  - 풀과 관목은 건조도에 따라 색을 바꾸고, 바위는 바이옴 색에 맞춥니다.
  - 잎은 투과광을 더합니다.
  - 지면 반사광(카메라 주변 바이옴 알베도)을 조도에 더합니다.

### 7.5 톤매핑, 오버레이, HUD

- **톤매핑**: 노출 적응, ACES, 어두운 환경에서의 암소시(푸르고 채도 낮은 야간 시각), 8비트 디더.
- **성능 오버레이** (F3, 오른쪽 위; `PerfOverlay`):
  - FPS, 프레임타임(최소/p99/최대), 240프레임 그래프
  - 렌더 스레드 CPU 분해, GPU 패스별 시간
  - RAM(RSS), VRAM(프로세스 사용량과 예산, 엔진 할당량)
  - 타일, 자연물 인스턴스 수, 잡 처리량
  - 글자는 stb_easy_font 사각형으로 만들어 한 번에 그립니다.
- **HUD** (걷기 모드, 왼쪽 아래): 체력, 지구력, 열량, 수분 막대와 이동 상태, 속도, 경사, 출력(W), 기온, 체온. 화면 가운데 점.

## 8. 하늘과 천문

- **시간**: UTC → TT → 율리우스일. 세차는 IAU 1976, 장동은 Meeus 근사를 쓰고 GAST로 지평 좌표를 구합니다. 대기 굴절은 Bennett 식입니다.
- **천체**:
  - 해: Meeus
  - 달: ELP 절삭판(위상, 밝기)
  - 행성 5개: Standish 케플러 요소
  - 정확도: 단위 테스트 기준 각오차 1′ 미만
- **별**: HYG v4.1(히파르코스 등)을 8.5등급까지 베이크하고(6.2만 개), 실행 시 8.0등급까지 약 4.1만 개를 그립니다. 고유운동을 게임 날짜의 epoch로 보정하고, B–V 색과 대기 소광을 반영합니다. 별 버퍼는 정적이고, 프레임마다 회전 행렬 하나만 갱신합니다.
- **대기**: Hillaire 2020 방식 LUT(투과율, 다중 산란, 해·달 하늘 LUT)를 씁니다. 달빛 LUT는 fp16 언더플로를 피하려고 단위 조도로 저장하고 샘플링할 때 곱합니다.

## 9. 플레이어와 물리

- **Jolt Physics 5.2** (`PhysicsWorld`):
  - **충돌 구역**: 플레이어 주변 128×128 높이장(1 m 간격, 렌더러와 같은 높이 함수)과 정적 충돌체로 이루어집니다. 충돌체는 나무 줄기 캡슐과 바위 LOD2 메시이고, 양치류·풀·관목은 통과합니다.
  - **재구성**: 구역은 워커 잡에서 만들고(셀 캐시 덕에 30–130 ms), 24 m 이동하면 수퍼바이저가 옛 바디를 빼고 새 바디를 넣으면서 원점을 다시 잡습니다.
  - **실행 위치**: 물리 스텝은 수퍼바이저 틱에서 돕니다(평균 30–70 µs). 정적 바디뿐이라 `PhysicsSystem::Update`가 필요 없습니다.
- **캐릭터** (`Player`, Jolt CharacterVirtual):
  - 캡슐 1.8 m, 눈높이 1.65 m.
  - 이동 상태(locomotion): walk, scramble(30–50°), slide, climb, air.
  - **속도**: Tobler 등산 함수의 수평 속도를 쓰고, 지면 평면을 따라 이동합니다. 달리기는 2.3배이고, 지치면 느려집니다.
  - **등반**: 45° 이상 면에서 Space를 누르고 있으면 면을 따라 0.35 m/s로 오릅니다. 꼭대기에서는 올라섭니다.
  - **낙하 피해**: 착지 속도가 7 m/s를 넘으면 다칩니다.
- **생체**:
  - 실제 이동으로 대사량(W)을 계산합니다: 수평 이동 + 몸 들어 올리기(효율 25%) + 내리막 제동 + 등반.
  - 지구력: 지속 가능 출력 약 750 W 기준으로 소모·회복합니다.
  - 열량(kcal), 수분(땀, 기온 의존), 심부체온(기온·출력 평형으로 수렴), 체력.
  - 기온: 에오세 온난 기준값 + 고도 감률 + 연교차 + 일교차.

- **원본 다운로드**: CMake가 `cmake/Download.cmake`로 받습니다. Poly Haven 에셋은 `tools/assets/fetch_polyhaven.py`가 `data/assets/polyhaven.txt` 매니페스트를 보고 MD5를 검증하며 받습니다.
- **나무 베이크** (`--crop`, `--lod0/1/2` 삼각형 예산):
  - 나무줄기는 meshoptimizer로 단순화합니다.
  - 잎은 잎 단위 연결 성분을 솎아 내고, 남은 잎을 `1/√비율`만큼(최대 3배) 키워 수관 밀도를 유지합니다.
  - 형식 `PHXTREE3`: 높이, 반지름, 재질(잎 여부, 텍스처 경로), LOD 메시 3개와 원본 메시(임포스터 굽기용).
- **종을 추가할 때 고칠 곳**:
  1. `data/assets/polyhaven.txt`
  2. `CMakeLists.txt`의 `PHX_TREES`
  3. `TreeMeshes`의 이름표와 `kSpeciesCount`
  4. `NaturePlacement`(배치 규칙, `kNatureScaleMul`)
  5. `VegetationRenderer`의 `kSpecies`(LOD 거리, 플래그)와 그림자 캐스터
  6. `veg_common.glsl`의 상수와 배열 크기, 종 번호를 쓰는 셰이더 분기
  7. `PhysicsWorld`의 충돌 규칙
- 라이선스 고지는 `data/README.md`에 있습니다. 별 데이터는 CC BY-SA이므로 크레딧에 "HYG Database by David Nash"를 표기해야 합니다.

## 11. 성능

1440p, `PHX_AUTOCLOSE` 측정값(GPU 패스 합, 개발 기기 기준):

| 장면 | GPU 합계 | 비고 |
|---|---|---|
| 화산 일대 지상 (스텝 + 숲) | 5.9 ms | csm 0.64, terrain 2.77, forest 2.10 |
| 사하라 지상 | 3.3 ms | 식생 적음 |
| 아마존 지상 | 6.5 ms | |
| 시베리아 타이가 지상 | 8.4 ms | 빽빽한 침엽수림: forest 3.8, csm 2.2 |

- 렌더 스레드 CPU는 프레임당 0.8–1 ms(갱신 + 기록 + 제출)입니다.
- 물리 스텝은 평균 30–70 µs입니다.
- 지형 타일 생성은 워커에서 약 9–11 ms/타일입니다(비동기).
- VRAM은 약 1.5 GiB입니다.

예산 목표는 60 fps(16.6 ms)이고, 근거리 지형 3 ms, 식생 5 ms, 그림자 3 ms 안팎입니다.

## 12. 디버깅 도구

- **F3 성능 오버레이**: §7.5.
- **로그**(5초마다): fps와 p99, 지형 타일 통계, GPU 패스별 시간, 식생 셀 수. 20 ms를 넘는 프레임은 구간별(GPU 대기 / 이미지 얻기 / 갱신 / 기록 / 제출) 경고를 남깁니다(초당 1회 제한).
- **시작 로그**: 기후 판정표(대표 지점별 기온, 강수, 건조지수, 바이옴, 산악도).
- **`PHX_TERRAIN_LEVELS=1`**: LOD 레벨 색칠. 스커트가 자홍색으로 보이면 인접 LOD 사이에 높이 불일치가 있다는 뜻입니다.
- **`PHX_CSM=0`**: CSM을 끄고 그림자 문제를 A/B 비교합니다.
- **`PHX_WALK=1/2/3`**: 스크립트 걷기 / 달리기 / 등반 테스트. 대사량, 생체 수치, 물리 스텝 시간을 1초마다 기록합니다.
- **`PHX_SCREENSHOT` + `PHX_POS` / `PHX_VIEW` / `PHX_DATE` / `PHX_TIME_RATE=0`**: 재현 가능한 스크린샷.
- **TSan 빌드**: `-DPHX_ENABLE_TSAN=ON`.
- **검증 레이어**: `PHX_VALIDATION=1`. 시스템에 vulkan-validation-layers 패키지가 있어야 합니다.

## 14. 알려진 한계와 미구현 항목

**월드**
- 1° 데이터라 실제 산의 세부 형태(예: 화산의 화강암 봉우리)는 없습니다. 산맥의 위치와 높이만 실제를 따릅니다.
- 규칙 기반 기후라 실제 분포와 다른 곳이 있습니다(예: 북미 대평원이 실제보다 건조).
- 높이는 에오세 해수면(+70 m), 기후는 현대 기준이라 아마존 저지대 일부가 바다입니다.
- 사막 단층애 면은 근거리에서 매끈합니다. 층리나 침식 홈 같은 근거리 디테일이 필요합니다.

**렌더링**
- 기획서에 있던 다음 기능은 아직 없습니다: 원경 큐브맵 캐시(4–32 km), 지평 각도 맵 그림자, 가상 텍스처, DLSS/FSR(지터, 모션 벡터, 업스케일러 추상화), 구름, 물(강, 호수).
- 빽빽한 침엽수림에서 식생 비용이 큽니다(타이가 forest 3.8 ms). 침엽수 LOD 예산을 조정할 여지가 있습니다.
- CSM 범위 밖에서는 지형 높이맵 그림자(근거리 맵 텍셀 약 3 m)의 계단 경계가 보일 수 있습니다.

**게임**
- 바다 위를 걸을 수 있습니다. 수영과 물 판정이 없습니다.
- 등반은 면 법선 기반으로 단순화했습니다. 홀드 자동 추출은 없습니다.
- 채집, 도감, 일지, 야영(M7), 날씨, 동물(M8)은 아직 없습니다.
- 성능 오버레이와 HUD는 자체 구현(stb_easy_font)입니다. 조작형 디버그 UI가 필요해지면 Dear ImGui 도입을 검토합니다.
